Method. A settlement is an AuthorizationUsed event emitted by the Base USDC contract (0x8335…2913) — the authoritative mark of an EIP-3009 transferWithAuthorization / receiveWithAuthorization execution. Value and counterparties are paired from the Transfer event in the same transaction.
Coverage. Protocol-agnostic by design — the ingest layer records the protocol, the entity layer does not care. Counted: x402/EIP-3009 on Base (AuthorizationUsed) and Solana (facilitator programs: Meridian meridian_x402, PayAI). Sampled: MPP on Tempo (tempo_mpp in stats.json, hourly estimates — raw chain activity, Stripe fiat rails are not observable). Direct wallet-to-wallet settlements are not counted on any chain — treat totals as a floor, not a market total.
Integrity. History here is never rewritten — and now provably so: every day the data files are hash-chained and Bitcoin-anchored (OpenTimestamps). Any attempt to alter a past day would break every later link. Verify the chain →
Independently verifiable — the only machine-payment data feed whose daily integrity you can check yourself, without trusting us: install the client and run pip install paycensus && paycensus-verify --base https://paycensus.com --ots — it re-computes the hash chain and validates the Bitcoin attestations from scratch. Exit code 0 = the numbers you cite were not touched after the day they describe.
