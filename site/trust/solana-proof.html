Solana address binding — proof format

Bind additional chain addresses to your verified domain profile. Domain control is proven once via DNS TXT; every payment address then hangs off the same verified identity, so buyers can check "who am I paying" across chains in one place.

1. What you prove

You sign an exact UTF-8 message with the ed25519 keypair whose public key is your Solana payment address (a Solana address is the base58 encoding of a 32-byte ed25519 public key). The message embeds the nonce of your verified record:

paycensus-addr-proof=<nonce>

Your nonce is shown in your account portal next to the verification (format: paycensus-verify=<hex>). The full signed message therefore looks like
paycensus-addr-proof=paycensus-verify=c05e1ee27fe0c75e2b907b9d842ee45f

2. Submit the proof

POST https://trust.paycensus.com/api/verify/addr-proof-solana
Content-Type: application/json

{
  "vid": 12,                        // your verification id
  "addr": "4iB9Z5…",               // Solana address (base58, 32-byte pubkey)
  "signature": "…"                  // base58 of the 64-byte ed25519 signature
}
ResponseMeaning
200 {"ok": true, …}Address bound to your verified profile (proven=1)
400Signature verification failed / domain not verified / bad payload
404Unknown vid

Base58 = Bitcoin alphabet (123456789ABCDEFGHJKLMNPQRSTUVWXYZabcdefghijkmnopqrstuvwxyz), leading zero bytes encoded as leading 1. No timestamps inside the proof — the nonce is single-purpose and tied to your verification record.

3. Python example (PyNaCl + base58)

from nacl.signing import SigningKey
import base58, json, urllib.request        # pip install pynacl base58

vid   = 12
nonce = "paycensus-verify=c05e1ee27fe0c75e2b907b9d842ee45f"  # yours
msg   = ("paycensus-addr-proof=" + nonce).encode()

sk   = SigningKey.generate()               # or the key owning your address
addr = base58.b58encode(sk.verify_key.encode()).decode()
sig  = base58.b58encode(sk.sign(msg).signature).decode()

req = urllib.request.Request(
    "https://trust.paycensus.com/api/verify/addr-proof-solana",
    data=json.dumps({"vid": vid, "addr": addr, "signature": sig}).encode(),
    headers={"Content-Type": "application/json"})
print(json.load(urllib.request.urlopen(req)))

To bind an address you already use, sign the message with that exact keypair — the submitted addr must be the base58 public key of the signing key, otherwise verification fails.

4. Where the bound address appears

Immediately after binding:

  • Trust status API and the seller profile endpoint:
    GET https://trust.paycensus.com/api/profile?domain=your.domain → addresses lists EVM + Solana with proven flags
  • The public multi-chain registry: paycensus.com/data/seller_profiles.json

What is verified vs self-declared: domain control (DNS TXT) and address ownership (this proof) are cryptographically verified by us. The contents of your /.well-known/x402.json (offers, descriptions) are seller-declared metadata and are labeled as such in the public data.

EVM note

EVM addresses use the same nonce message with EIP-191 personal_sign (endpoint /api/verify/addr-proof, already live). More chains (or more curves) follow the same pattern: one verified domain, one profile, many addresses.
